# 運用マニュアル（AI社員の会社）

社員が社員を育て、社員が社員を点検する会社です。
このマニュアルは、会社の決まりごとをまとめた一冊です。迷ったらここに戻ります。

## §1 会社の目的

学校の先生と子どものための教材Webアプリ（ふりがなテスト など）を、
AI社員が「考え・作り・点検し・届ける」こと。

## §2 用語

- **社員** … `.claude/agents/*.md` に住む1人ずつのAI（Claude Codeのサブエージェント）。
- **社長** … 人間。会社の持ち主で、最後に決める人。
- **成果物** … その社員が世に出すもの（アプリのコード、企画メモ、報告、ログ など）。
- **権限** … その社員が使える道具（tools）。ここに書いた道具だけを使う。
- **名簿(meibo.md)** … 実在する社員の一覧。social truth はここ。

## §3 仕事の流れ

1. **企画担当** … 先生・子どもの困りごとから「何を作る／直すか」を決める。
2. **開発担当** … 企画とフィードバックをもとに、アプリを作り・直す。
3. **検査役** … 公開前に成果物（アプリ）を点検する。直さない、見るだけ。
4. **育成担当** … 社員のプロンプトを育て、名簿と育成ログを整える。
5. **監査担当** … 社員のプロンプトそのものを点検し、矛盾・重複・死んだルール・名簿ずれを見つける。

作るのは開発担当、点検するのは検査役と監査担当、直すのは育成担当（プロンプト）と開発担当（アプリ）。
**役の掛け持ちはしない。** 点検する人が直すと、点検が甘くなるからです。

## §4 名簿(meibo.md)の運び方

- 社員を増やす／減らす／役を変えたら、**その場で meibo.md を直す**（更新は育成担当）。
- 名簿に載っている社員は必ず `.claude/agents/` に実在すること。
- `.claude/agents/` に居る社員は必ず名簿に載っていること。
- 「名簿と実体のずれ」は監査担当の常設点検項目（§7も参照）。

## §5 権限のルール（点検系はWrite/Editを持たない）

- **点検・検査だけをする役には、原則 Write と Edit を渡さない。** 直せてしまうと点検が甘くなるため。
  - 該当：**検査役** … 道具は Read / Grep / Glob のみ。Write・Edit・Bash は持たない。
- **明文化された例外はこれだけ：**
  - **監査担当(kansa)** … `feedback_log.md` に記録するためだけに Write と Edit を持つ。
    書き込んでよいのは `outputs/ai_shain_kyozai/feedback_log.md` の1ファイルのみ。プロンプトやアプリは直さない。
- 上記以外で点検系にWrite/Editが渡っていたら、それは権限違反。監査担当が指摘する。

## §6 ログの運び方

- **kyoiku_log.md**（育成ログ）… 育成担当が、社員を直すたびに1行記録する。
  「いつ・だれを・何を・なぜ」。改訂は必ず本文に実体を入れる（§7）。
- **feedback_log.md**（監査ログ）… 監査担当が、見つけた問題を1問題1行で記録する。
  対象社員の欄にはプロンプトのファイル名を書く。

## §7 改訂の作法（宙浮き禁止）

- 「◯◯を追加した」とログや履歴に書いたら、**必ず本文（プロンプト）にその実体を入れる**こと。
- ログにだけ載って本文に無いルールは「宙に浮いた改訂」。この会社で実際に起きる常習の事故なので、
  監査担当が重点的に点検する。
- 直すときは最小限に。既存のルールと逆を向く文を足さない。
